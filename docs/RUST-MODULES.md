# Выбираемые подключения на Rust

В хосте есть три исполняемых формата:

| kind | Выполнение | Выбор кода |
|---|---|---|
| `module` | Rust-библиотека внутри процесса ядра | Cargo feature при сборке |
| `lua` | Отдельная ограниченная VM внутри ядра | Установка скрипта |
| `native` | Отдельный процесс, JSON-протокол | Переходная совместимость и внешние программы |

У встроенного модуля `id`, `main` и единственное значение `provides` совпадают.
Хост запускает только известную реализацию, включённую в сборку. Архив модуля
содержит манифест, а исполняемый код уже находится в выбранной прошивке.
Неизвестный или не включённый в сборку модуль остаётся остановленным с причиной в списке плагинов.

Перенесены [Home Assistant](../plugins/homeassistant/README.md) и
[Яндекс Умный дом](../plugins/yandexhome/README.md). Они находятся в отдельных
workspace crates `jarvis-homeassistant` и `jarvis-yandexhome` и подключаются
к ядру опциональными зависимостями. Набор по умолчанию — ядро и Lua;
`--no-default-features` убирает Lua. При отсутствии feature `homeassistant`
ядро не включает эту библиотеку и её WebSocket-клиент.

Добавлен [VPN на Rust](../plugins/vpn-rust/README.md): опциональный crate
`jarvis-vpn` и feature `vpn`, VLESS TCP/WebSocket, TLS, REALITY и Vision,
локальный SOCKS5, проверка настроек и остановка через хост. Имитация браузерного
TLS fingerprint пока отсутствует; прежний native-пакет — отдельная реализация.

```sh
cd jarvis
cargo build --release --target aarch64-unknown-linux-musl --features homeassistant
cargo build --release --target aarch64-unknown-linux-musl --features homeassistant,yandexhome
cargo build --release --target aarch64-unknown-linux-musl --features homeassistant,yandexhome,vpn
cargo build --release --target aarch64-unknown-linux-musl --no-default-features
```

В `scripts/rs-build.sh` доступны `JARVIS_FEATURES` (список через запятую)
и `JARVIS_NO_DEFAULT_FEATURES=1`. `jarvis modules` выводит JSON-массив имён
встроенных модулей до запуска настроек и оборудования. Тот же список возвращают
`/healthz` и поле `modules` у `/api/plugins`.

Для голоса, инструментов и веб-панели провайдер теперь может быть отдельным
процессом или встроенным модулем с общим `request`/`notify`.
ChatGPT поддерживает оба формата. Rust-модуль включает OAuth, Codex SSE и голосовой
WebRTC с Opus. При выбранном VPN прямой UDP запрещён; для звонка нужен TCP ICE.
OpenAI, Gemini, Grok и ElevenLabs также выделены в опциональные Rust-модули.

Сетевой маршрут облачного модуля приходит от хоста через сервис `network`.
Встроенный Яндекс использует собственный HTTP-клиент с этим маршрутом и не
зависит от процессного SDK. Панель получает выбранные провайдеры через поле
`providers` у `/api/state`; экран подключения связывается с реальным плагином.

Каталог добавляет манифесты из текущей сборки. Их установка выполняется локально.
Отключение встроенного модуля отменяет текущие запросы. Если отдельный модуль
отключён или удалён, объединённый прежний плагин не подменяет его автоматически.
При наличии отдельного Home Assistant старый `home` не устанавливается автоматически
только из-за сохранённых настроек уже выделенных HA или Яндекса.
